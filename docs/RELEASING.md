# 发布约定

从仓库根目录使用 `scripts/package-release.ps1 -Iscc <ISCC.exe>` 构建发行包，内部统一调用 `native-rewrite/package-release.ps1`。主程序保持名为 `DoubaoVR.exe`，原安装器 AppId 不变。根目录 `VERSION` 是版本号的唯一来源，C++、C#、安装器与发布文件共同使用该版本。

主分支不保留旧 Python 工程、测试代码、验证记录或开发指令文件；旧版源码通过 v0.2.4 标签和本地备份查阅。中文安装资源位于 `native-rewrite/installer/ChineseSimplified.isl`，当前构建不依赖旧 Python 工程目录。普通源码构建不要求本地测试资料；正式发布使用维护者本地的完整验证流程，缺少资料时必须终止发布，不允许静默跳过。动效测试类仅用于本地验证构建，不编入正式程序。

- 每次发布提供 Windows 安装 EXE、免安装 ZIP 与各自的 SHA256。
- 安装器 AppId 必须保持不变，保留 `UsePreviousAppDir=yes`，让后续安装默认沿用原路径。
- 旧版用户配置存放在 `%LOCALAPPDATA%\DoubaoVR`，v0.2.5 使用 `%LOCALAPPDATA%\DoubaoVR.Native`，两处均不得随安装、升级或卸载清空。旧版配置只在没有现有配置时导入。
- 安装文件从发布白名单构建，不收集运行目录中的个人设置、日志、测试脚本、截图、原稿或开发工具。
- 更新日志只列用户可见的新增功能、行为变化和修复的问题，不记录开发对话、内部方案编号或测试过程。
- 修复页面切换问题时检查连续画面，并确认页面内容完整；不能仅凭切换结束后的截图判断。
- 发布前核对安装器沿用原路径、运行中覆盖安装、配置保留和下载文件校验值。

## 安装器验收

- 安装器须从普通发行目录启动，记录实际文件 SHA256、Windows 版本、账号类型和运行完整性级别。带低完整性隔离标签的开发工作区不代表普通用户的安装环境；不得通过移除工作区隔离权限或降低系统安全策略让验收通过。
- 分别验证 Windows 10、Windows 11 的干净环境，使用没有预装 Python、没有旧配置的普通用户账号。编译成功和单元测试通过不能替代安装验收。
- 验证全新安装、中文及含空格路径、二次覆盖安装、沿用原安装路径、设置保留、快捷方式启动和卸载后设置保留。
- 分开记录安装器引导阶段、程序启动、豆包字幕捕获和 SteamVR 显示的结果。无法创建 `is-*.tmp` 目录属于引导阶段失败，不能以程序源码修复或签名代替验证。
- 尚未通过的项目须明确标为未验证；存在已知安装阻断时，不得将候选安装包作为已验证的正式安装版发布。
